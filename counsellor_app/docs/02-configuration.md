# 2. Configuration & Prerequisites

## 2.1 Prerequisites

| Requirement | Notes |
|-------------|-------|
| **Python 3.10+** (3.11 recommended) | `python --version` |
| **pip** | ships with Python |
| A **Google service account** | with access to the Data sheet — see `docs/05` |
| The **Data sheet ID** | already known: `1ReJVPl_Y8WnOl_P2sui_uC1jjZXVk0dWqNWRcXGVHCw` |
| A host to run it on | the existing automation PC, a small VM, or any always-on machine |

Python packages (installed via `requirements.txt`): `fastapi`, `uvicorn`,
`pydantic`, `PyYAML`, `bcrypt`, `gspread`, `google-auth`.

No database server is needed — durability uses a local SQLite file that Python
creates automatically.

## 2.2 Configuration file

All configuration lives in **`config.yaml`** in the `counsellor_app/` folder.
Start from the template:

```bash
cp config.example.yaml config.yaml
```

Then edit it. Every setting and its default:

| Key | Default | Meaning |
|-----|---------|---------|
| `data_sheet_id` | `1ReJVPl…VHCw` | The Google Sheet that is the system of record. |
| `active_tab` | `IntelliBI Lead Information Active` | Tab holding the current record per lead. |
| `active_tab_aliases` | `[IntelliBI Lead Information Result]` | Alternate names the code will also accept for the active tab. |
| `inactive_tab` | `IntelliBI Lead Information InActive` | Tab holding archived prior versions. Created automatically if missing. |
| `service_account_file` | `credentials/service_account.json` | Path to the Google service-account key JSON. |
| `db_path` | `data/store.db` | Local SQLite cache + write-behind journal. |
| `reconcile_seconds` | `300` | How often to re-read the sheet to catch out-of-band edits. |
| `sync_batch_max` | `50` | Max queued writes flushed to Sheets per cycle. |
| `sync_tick_seconds` | `2.0` | How often the background sync runs. |
| `session_secret` | `CHANGE_ME…` | Secret used to sign login cookies. **Must be changed.** |
| `session_hours` | `12` | How long a login stays valid. |
| `google_oauth_enabled` | `false` | Optional Google Workspace login (see `docs/04`). |
| `google_client_id` | `""` | OAuth client ID (only if the above is true). |
| `allowed_email_domain` | `""` | Restrict logins to this email domain (optional). |
| `host` | `0.0.0.0` | Interface to bind. `0.0.0.0` = reachable on the LAN; `127.0.0.1` = local only. |
| `port` | `8600` | Port the app listens on. |
| `counsellors` | `[]` | The account allow-list (see below and `docs/04`). |

## 2.3 Environment-variable overrides

Any of these environment variables override `config.yaml` at startup (useful for
secrets you don't want in the file, or for containers):

| Variable | Overrides |
|----------|-----------|
| `INTELLIBI_APP_DATA_SHEET_ID` | `data_sheet_id` |
| `INTELLIBI_APP_SERVICE_ACCOUNT` | `service_account_file` |
| `INTELLIBI_APP_SESSION_SECRET` | `session_secret` |
| `INTELLIBI_APP_DB_PATH` | `db_path` |
| `INTELLIBI_APP_HOST` | `host` |
| `INTELLIBI_APP_PORT` | `port` |
| `INTELLIBI_APP_SECURE_COOKIE` | if set, marks the session cookie `Secure` (use behind HTTPS) |

## 2.4 The counsellor allow-list

Counsellors are listed under `counsellors:` in `config.yaml`. Each entry:

```yaml
counsellors:
  - email: "meera@intellibiinnovationstechnologies.in"
    name: "Meera Nair"
    counselling_by: "Meera Nair"      # the exact value written to the "Counselling By" column
    role: "counsellor"                # counsellor | admin
    password_hash: "$2b$12$…"         # bcrypt hash — generated by the CLI, never typed by hand
    active: true
```

**Never put a plaintext password in this file.** Use the admin CLI, which prompts
for the password and writes only the bcrypt hash (see `docs/04`):

```bash
python -m app.manage_users add meera@intellibiinnovationstechnologies.in "Meera Nair" "Meera Nair"
```

## 2.5 What must be changed before production

1. `session_secret` → a long random string. Generate one:
   ```bash
   python -m app.manage_users secret
   ```
2. At least one real counsellor account added via `python -m app.manage_users add …`.
3. `service_account.json` placed in `credentials/`.
4. Decide `host`: `127.0.0.1` if you'll use a reverse proxy / only local access;
   `0.0.0.0` to serve the LAN directly.

## 2.6 Files that must never be committed to git

The provided `.gitignore` already covers these, but for awareness:

- `config.yaml` (contains the session secret and password hashes)
- `credentials/*.json` (the Google service-account key)
- `data/` and `*.db*` (local cache/journal — machine-specific)
